# Project instructions

- For behavior or scope changes, find the relevant contract through `.scratch/calcplus/spec/README.md`; contracts take priority over summaries. Read the milestone plan only when selecting or gating a milestone.
- Read `CONTEXT.md` when changing domain terms. Read `CONTRIBUTING.md` before changing dependencies or assets, or before committing.
- Run checks on the maintainer's computer only. Never run tests or checks on GitHub. For code changes, start with focused checks; before committing, use the local checks in `CONTRIBUTING.md`. Read command names from `package.json`.
- Keep work within the request. Ask before changing first-release scope or architecture; record an approved architecture decision in `docs/adr/`.
- Handle small, self-contained changes directly. Use the orchestrator for milestone work. Bring in research or documentation help only when the task needs it.
- Commit or push only when the user asks. Follow `CONTRIBUTING.md` for signed commits.
- Each milestone uses a light sense check only. Deeper hardening runs only when the user explicitly kicks it off, and nothing automatic starts it.
- Write plainly and avoid abbreviations in replies. Preserve exact code, commands, and file paths.
