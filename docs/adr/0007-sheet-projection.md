# The grid reads a projection of the workbook, never the workbook

The canvas renderer, the cell editor and the DOM-cell fallback all read one read-only **sheet projection** that is versioned with the document; the accessibility mirror joins them in v2. It is built lazily for the visible window, returns ready-to-paint records — display text after number formats and conditional formatting, fill, font, border, alignment, merged span, plus the raw value and formula text the editor needs — and answers geometry questions by index rather than by iteration. Selection, scroll and focus are passed in by the caller and never become part of the document version.

**Considered options:** the renderer reading the model directly (fastest to start, but the canvas, the mirror and the fallback would each re-derive formatting, conditional formatting and merges, and they would drift); a full copy of the sheet rebuilt after every change (clean, but copying 250k cells on every keystroke); the model pushing per-cell updates to the grid (fast, but it couples the grid to the command system and makes tests stateful).

**Why:** consumers must never disagree about what a cell looks like. One description, produced once per version, is the only arrangement in which the canvas and, in v2, the screen-reader layer are guaranteed to match. Lazy evaluation keeps the cost proportional to what is on screen, and keeping selection out means scrolling and selecting cannot mark the document dirty (invariant 8).

**Consequences:** the projection is the single interface between model and renderer, specified in [workbook model §11](../../.scratch/calcplus/spec/workbook-model.md); a command bumps the version and the next paint rebuilds; conditional formatting is resolved into the record and never mutates the model (invariant 11); the number-format cache stays in the `NumberFormatter`, keyed by style and value; the DOM-cell fallback is a drop-in for the canvas because both consume the same records; a lint rule stops the renderer importing model modules.
