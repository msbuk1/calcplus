# Patch the original XML on save; rebuild only what changed

calcplus saves by copying the original bytes of a part and rewriting only the smallest changed unit: rows outside an edit are copied verbatim, and inside an edited row only the changed cells are regenerated. Unknown elements, attributes, namespace declarations and their order therefore survive an edited save. Small parts — charts, drawings, pivot definitions — are edited as trees and re-emitted, because they are kilobytes and because chart series ranges must be rewritten. Both paths sit behind one part-patch interface.

**Considered options:** rebuilding every modelled part from the canonical model (simple, but it can only write what the model understands, which is the failure this architecture exists to avoid); a tree rewrite for every part (simplest correct code, but a 250k-cell sheet is 10–20 MB of text and a tree costs several times that on top of the ~250 MB formula engine, breaching the 500 MB guaranteed ceiling, and a 1M-cell sheet is far worse); position-based patching for every part including charts (unnecessary complexity on kilobyte parts); two unrelated writers (the sheet and chart paths would drift).

**Why:** "no silent loss" has to hold for edited files, not only for no-op saves, and the memory contract forbids holding a worksheet as a tree. The chosen parser reports the character position while reading, so byte slicing needs no new dependency. Copying the smallest unchanged unit gives byte-identical untouched rows, preserves cell-level extensions, and keeps memory proportional to the edited region rather than to the sheet.

**Consequences:** the patch writer is the riskiest component of milestone 1 and lands before anything depends on it; M1 patches cells only, and row/column shifting arrives with the structural-edit milestone on the same writer; tests assert unknown-element order and byte-identical untouched rows, plus a property test over random edits; a worksheet that cannot be cut safely falls back to a tree rewrite below 16 MB and refuses the save above it while keeping the recovery copy; every transformed part appears in the export report.
