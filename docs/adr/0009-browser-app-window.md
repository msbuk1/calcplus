# Open the app in a Chromium app window, not a browser tab

The launcher opens calcplus in an **app window**: an installed Chromium browser started with `--app=<url>`, which gives a window with no tabs, no address bar and no bookmarks. The app reads as its own window rather than a tab in a browser the user is already using, which is what the maintainer asked for — "it'll save a bit of window real estate". The window uses the **user's own browser profile**, not a dedicated one. When no Chromium browser is installed, or `--no-app-mode` is passed, the launcher opens the default browser exactly as before.

**Considered options:** an ordinary tab in the default browser (the previous behaviour, and what `distribution.md` §2 and §4 described); an app window in an installed Chromium browser using the user's own profile (chosen); an app window using a dedicated `--user-data-dir` beside the executable; a desktop wrapper embedding a browser engine such as Tauri or Electron.

**Why:** the app window is the only option that buys the real estate without hiding data. A dedicated profile looks tidier — it never disturbs the user's browser session — but IndexedDB is per-profile, so recovery copies, recent files and file handles would live somewhere the user cannot see by opening the URL by hand. That is the same failure `distribution.md` §2 warns about with `--port N`: storage that silently looks like data loss. Using the user's own profile keeps one storage area per browser, so the state the launcher shows is the state the browser shows. A desktop wrapper is already ruled out by `distribution.md` §22, and app mode is not one: it drives a browser the user already has, it embeds no engine and it provides no native menus. An ordinary tab keeps the real estate cost and gives nothing back.

**Consequences:** app mode needs a Chromium browser. Chrome is preferred and Edge is the fallback, and Edge ships with every Windows 10 and 11 install, so a Chromium window is available there without installing anything. **The launcher does not honour the user's default browser when that browser is not Chromium** — a Firefox user gets a Chrome or Edge window instead of a Firefox tab. Their Firefox state is untouched and still there if they open the URL by hand, but the two will not match. That is a real consequence, it is recorded in the ADR rather than hidden, and `--no-app-mode` is the escape that restores the old behaviour exactly. The startup output names the browser that opened the window, so which storage area is in use is visible rather than inferred. The launcher remains a distribution shell: no engine is embedded and no native menus appear. Linux and macOS take the same path where a Chromium browser is installed.

**Spec alignment:** [distribution](../../.scratch/calcplus/spec/distribution.md) §2 and §4 are updated in the same change to describe the app window and the `--no-app-mode` escape. The rest of §2 is unchanged and still holds: the server is bound to the literal `127.0.0.1` on the stable preferred port, `--port N` still opens a separate origin and storage area and says so, and no outbound calls are made. This ADR is the decision of record for how the app is opened.
