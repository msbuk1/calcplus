# calcplus — Excel desktop clone spec

Type: map
Status: open

## Destination

A build-ready spec package for **calcplus**, a browser-based, single-user clone of Excel desktop (Microsoft 365): a core credible spreadsheet — grid and editing, formatting, formulas, multi-sheet workbooks, high-fidelity `.xlsx` round-trip — at functional, near-identical UI fidelity. The package is a PRD, a technical design (workbook model, architecture, ADRs) and phased milestones. No backend, but a data model that does not preclude co-authoring later.

## Notes

- **Effort slug**: `calcplus`; tracker is local markdown under `.scratch/calcplus/`.
- **Fidelity reference**: Excel desktop / Microsoft 365. When Excel and "clean design" disagree, match Excel — the product's promise is familiarity.
- **V1 scope cut**: core credible spreadsheet, fixed by the [feature matrix](spec/feature-matrix.md). Charts, advanced data tools and authoring of read-only fidelity features are v2; PivotTables and macros are never.
- **Constraints**: browser app; single-user; no backend; high-fidelity `.xlsx` import and export; no pixel-perfect requirement, but near-identical chrome.
- **Project licence**: GPLv3 (decided while resolving ticket 02). Dependencies must be GPLv3-compatible; the free HyperFormula edition is used.
- **Distribution**: static host plus a bundled per-OS launcher; no backend. See the [distribution contract](spec/distribution.md).
- **Execution carried into the map**: because the destination is an artifact, ticket 15 assembles the spec package. Every other ticket resolves a decision.
- **Skills for sessions**: `grilling`, `domain-modeling`, `prototype`, `research`.
- **Domain vocabulary**: [CONTEXT.md](../../CONTEXT.md).
- **Research artifacts**: `.scratch/calcplus/research/<slug>.md` (files rather than throwaway branches, so they travel with the map).

## Decisions so far

- [Define the v1 feature matrix and acceptance criteria](issues/01-feature-matrix.md) — v1 scope contract in the [feature matrix](spec/feature-matrix.md): core editing, sort/AutoFilter, full cell and number formatting, render-only conditional formatting/comments/hyperlinks/protection; v2 and never classified per area.
- [Define formula semantics and function coverage](issues/02-formula-semantics.md) — 52 published functions with Excel-exact errors and coercion; A1/mixed/cross-sheet/names; 1900 and 1904 dates; no spill, read-only legacy arrays, volatile TODAY/NOW; circular references warn and show `#CIRC!`. Contract: [formula semantics](spec/formula-semantics.md).
- [Formula engine: build vs buy](issues/03-formula-engine.md) — HyperFormula behind a narrow `FormulaEngine` port; **amended by ticket 02**: calcplus is GPLv3, so use the free GPLv3 edition, and the published contract is the 52-function set. **Re-evaluated in ticket 24:** IronCalc 0.9.1 rejected for v1 (no 1904 dates, fake 1900 leap day wrong, `.xlsx` layer rewrites rather than preserves); HyperFormula stays with a documented config/shim list.
- [`.xlsx` import/export approach](issues/04-xlsx-io.md) — preservation-first in-house OOXML layer (JSZip/fflate + saxes): model v1 features, copy unmodelled parts verbatim, patch only dirty parts, append-only style/shared-string tables; SheetJS/ExcelJS are extractors, not storage engines.
- [Grid rendering approach](issues/05-grid-rendering.md) — custom hybrid grid: Canvas 2D surface (cells, gridlines, headers, selection, fill handle, frozen/split panes) + DOM overlays for editing/focus and an ARIA grid mirror; no third-party grid foundation. **Confirmed by ticket 17:** the custom spike met the frame budget and exposed 403 grid cells to assistive technology; Univer was rejected (its chrome, model and `.xlsx` layer are not ours, and its canvas exposes 0 grid cells). The a11y mirror is a first-milestone gate and a DOM-cell renderer stays behind the `RenderFrame` seam as the fallback. Spec: [grid spike](spec/grid-spike.md).
- [Clipboard and Excel interop](issues/06-clipboard-interop.md) — HTML-first (`text/html` Excel dialect) with TSV fallback; formulas best-effort, `.xlsx` is the fidelity channel, and clipboard is never a dependency for correctness.
- [Workbook data model](issues/07-workbook-model.md) — canonical workbook model as the source of truth; sparse typed cells, shared append-only style table, stable IDs, document/view split, engine-derived dependency graph, JSON snapshot + opaque bytes, command log for undo and co-authoring, anchor index for preserved parts. Spec: [workbook model](spec/workbook-model.md); [ADR 0001](../../docs/adr/0001-canonical-workbook-model.md).
- [File handling and persistence](issues/08-file-persistence.md) — in-place save via File System Access API with picker/download fallback; JSON recovery copy in IndexedDB about 3 seconds after edits; local recent list with handles; close/save conflict prompts; unsupported parts preserved; one workbook per tab; local-first and sync-ready. Spec: [persistence](spec/persistence.md).
- [Command system, keyboard parity and undo/redo](issues/09-command-undo.md) — one command registry for every surface; commands return range-based change sets; one transaction per action; 200-entry/64 MB undo bound; Excel-compatible shortcut map with documented browser conflicts and alternatives; focus zones; replayable log with `seq`/`actorId` for future co-authoring. Spec: [command system](spec/command-system.md).
- [UI chrome architecture and ribbon shell prototype](issues/10-ui-chrome.md) — Variant A ribbon is primary; Variant B compact is the responsive mode below ~900 px; Variant C rejected. React 19 + TypeScript + Vite shell; command-bound primitives; only the grid scrolls. Spec: [UI chrome](spec/ui-chrome.md); [prototype on branch `prototype/ui-shell`](https://github.com/msbuk1/calcplus/tree/prototype/ui-shell/prototype/ui-shell).
- [Prior art: what calcplus can learn from GenOffice](issues/16-prior-art-genoffice.md) — validates preservation-first `.xlsx`; shared formulas, structural-edit reference rewriting and the edge-case tail are the real cost; the Univer buy path deserves a stress test.
- [Number-format engine: build vs buy](issues/18-number-format-engine.md) — `numfmt` 4.1.3 (MIT) behind an internal interface, plus owned Excel seams: built-in ID table, 1904 adapter, width layout, colour/palette, locale grouping, invalid-format fallback and style-table round-trip. `ssf` is a differential test oracle only.
- [Print and PDF pipeline](issues/21-print-pdf.md) — own pagination in a pure `PrintPlanner`/`PrintPlan`; render pages as inline SVG for preview and paper, PDFKit for vector PDF export, and 300 DPI canvas only as a font/script fallback.
- [IronCalc/WASM vs HyperFormula for the 52-function contract](issues/24-ironcalc-vs-hyperformula.md) — keep HyperFormula GPLv3; IronCalc 0.9.1 rejected for v1 (no 1904 dates, fake 1900 leap day wrong, `.xlsx` layer rewrites rather than preserves).
- [Distribution and local-run model](issues/25-distribution.md) — static hosted build plus a bundled per-OS launcher (loopback-only server, opens the default browser); launcher is offline, updates are manual, Chromium-first file access with Safari/Firefox fallback, no accounts or telemetry. Contract: [distribution](spec/distribution.md).
- [Launcher technology and release packaging](issues/26-launcher-technology.md) — Go stdlib-only launcher (embedded static build, `127.0.0.1`, stable port), one binary per OS; Windows signed portable `.exe`, macOS notarized universal `.app` in a DMG, Linux static tarball; about US$220/year signing cost; random ports would break origin-scoped storage.
- [Performance targets and benchmarks](issues/11-performance.md) — reference machine is a mid-range 2023 laptop on desktop Chromium; guaranteed 250k touched cells / 50k formulas, degraded 1M / 200k, refuse above; 500 MB / 1 GB / 1.2 GB memory ladder; cold open 0.8/2.5/5/15 s; 60 fps scroll, 50 ms direct, 100 ms commit; 100k-cell paste in 1 s; fan-out is a named corpus case; 20% PR regression gate plus nightly absolute budgets; staged visible degradation. Contract: [performance](spec/performance.md).
- [`.xlsx` file-compatibility contract](issues/12-file-compat-contract.md) — three tiers: modelled and editable (Tier A, semantic round-trip), preserved and not editable (Tier B, byte-identical parts, anchors transformed or the edit blocked), and rejected (Tier C, clear message and no partial import). No-op save returns the original bytes; style and shared-string tables append-only; formula text never rewritten; macros preserved but never run; external links and pivot caches never refreshed; compatibility and export reports surface everything. Contract: [file compatibility](spec/file-compat.md).
- [Stress-test the grid decision: custom vs Univer](issues/17-grid-spike-univer.md) — custom canvas confirmed, Univer rejected for v1, HyperFormula unchanged. Custom: 7.9 KB gzip, ~125 ms warm to visible, 16.8 ms p95 scroll, 403 exposed grid cells. Univer: 1.78 MB gzip entry, ~300-400 ms warm, 18.9-20.6 ms p95, 0 grid cells, no open-source `.xlsx`. Accessibility mirror becomes a first-milestone gate; DOM-cell renderer stays as the fallback. Spec: [grid spike](spec/grid-spike.md); prototype on branch `prototype/grid-spike`.
- [Sort and AutoFilter semantics](issues/19-sort-autofilter.md) — sort is a stable row permutation over the selected range with Excel's documented order and blanks last; formulas move and relative references shift; hidden rows stay put; uniform one-row merges move, mixed merges and tables/arrays block. AutoFilter: one per sheet, row 1 header, typed checklist or two AND/OR conditions per column, columns combine with AND; manual-hidden and filter-hidden rows are separate layers; structural edits transform the range; XML round-trips and unsupported filters are preserved read-only. Spec: [sort and AutoFilter](spec/sort-autofilter.md).
- [Conditional-formatting rendering](issues/20-conditional-formatting.md) — render cell-value, text, date/time-period, top/bottom, duplicate/unique, colour-scale, data-bar and icon-set rules; preserve formula-based, above-average, blank/error and formula-threshold rules unpainted and report them. Priority order, property merge, stop-if-true, manual formatting shows through; blanks coerce to 0; text uses display text with wildcards; merged-anchor evaluation; per-pane clipping; zoom-scaled visuals. Indexed caching: visible evaluation under 4 ms, 100k-cell statistics under 200 ms. Base plus x14 XML, append-only dxfs, range transforms. Spec: [conditional formatting](spec/conditional-formatting.md).
- [Accessibility target for the grid](issues/22-accessibility.md) — WCAG 2.2 AA for the chrome and the DOM mirror; the canvas is `aria-hidden`. `role="grid"` with absolute counts/indices, headers, merged spans, roving tabindex, persistent active cell, `aria-selected` and a polite live region. Every command keyboard-reachable; F6 zone exit; 2 px 3:1 focus ring; forced-colours canvas palette; 200% browser zoom; 24 × 24 chrome targets. axe-core and Playwright in CI, manual NVDA/JAWS/VoiceOver sign-off before the grid milestone. Spec: [accessibility](spec/accessibility.md).
- [Testing and Excel-conformance strategy](issues/13-testing-conformance.md) — Excel 365 on a Windows runner is the authoritative oracle; stored goldens run on pull requests, and LibreOffice and `ssf` are differential aids only. Exact types; numbers within 1e-9 relative / 1e-12 absolute. Vitest + Playwright + fast-check + axe; fakes only at the clock, file, clipboard and Excel boundaries. Full 52-function, file, sort/filter/CF, grid, visual, accessibility and performance gates; pull requests under 15 minutes, nightly full, oracle on a schedule. Spec: [testing and conformance](spec/testing-conformance.md).
- [Milestones and phasing](issues/14-milestones.md) — eight hybrid vertical-slice milestones: walking skeleton, grid foundation, formula/model, formatting/workbook, data tools, file fidelity, output/hardening, conformance/release. Three engineers, 62-90 person-weeks plus 20% contingency, no calendar dates. Five scheduled risk spikes; a demo and gate per milestone. v1 done requires the ticket 13 release gate, launcher artifacts, complete docs, AT sign-off and no P0/P1/data-loss bugs. Plan: [milestones](spec/milestones.md).
- [Project licence: GPLv3 and dependency compliance](issues/23-licence-compliance.md) — GPL-3.0-only made real with `LICENSE`, `NOTICE`, `THIRD_PARTY_NOTICES.md`, `CONTRIBUTING.md`, `CONTRIBUTORS.md` and `README.md`. HyperFormula GPL-3.0-only is the binding constraint; every distributed dependency is compatible. Distribution obligations, font and trademark rules, DCO sign-off and the CI licence gate are recorded. Note: [licensing](spec/licensing.md).

## Not yet specified

- Localization of the UI and of function names.
- Formula-bar and name-box edge behaviours.
- Grid interaction edge cases not fixed by the matrix: fill-handle options, merged-range selection, IME/bidi text, selection scrolling.

## Out of scope

Everything marked **V2** or **NEVER** in the [feature matrix](spec/feature-matrix.md) is out of scope for this effort. Highlights:

- **Real-time co-authoring, accounts, cloud sync, sharing** — v1 is single-user. The model must not preclude it, but the feature is a later effort.
- **VBA/macros execution, Office Scripts, add-ins.** (`.xlsm` files open and save with macro parts preserved.)
- **PivotTables, Power Query, Solver/Goal Seek, Data Analysis ToolPak, Consolidate.**
- **Charts, images, shapes, sparklines.**
- **Advanced data tools**: tables, data validation, advanced/colour/Top-10 filters. (Sort and AutoFilter are in v1.)
- **Authoring of read-only fidelity features**: conditional formatting, comments, hyperlinks, defined names, protection, themes and named styles.
- **Paste Special, fill series, split view, full page setup, localization, dark mode.**
- **Formula features deferred to v2**: R1C1 notation, 3D ranges, structured table references, external-link refresh, dynamic arrays/spill, iterative calculation, manual calculation mode, union/intersection operators, localized function names.
- **Native desktop and mobile/touch apps** (the distribution launcher is in scope; a Tauri/Electron desktop app is not).
- **Legacy `.xls` binary and ODS formats.**
