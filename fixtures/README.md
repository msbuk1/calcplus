# Fixtures

Small committed workbooks. Regenerate with `npm run fixtures`
(`scripts/generate-fixtures.mjs`). The generator is deterministic: the ZIP
entry date is fixed and the XML payloads are handwritten.

| File | Purpose |
|---|---|
| `compat/identity-minimal.xlsx` | No-op open → save returns the original bytes (file-compat F1 shape). |
| `compat/m1-chart-unknown.xlsx` | M1 walking skeleton workbook: shared strings, inline string, number, boolean, error, formula with cached result, styles, merged range, freeze pane, a chart with its drawing/VML parts, a `<legacyDrawing>`, a `<phoneticPr>` and an unknown `<extLst>` with a custom-properties extension. The edited save test asserts the children and their order survive in the dirty worksheet part, and the part inventory proves the chart/drawing/VML bytes are untouched. This is a preservation fixture; the manual Excel capture uses `oracle/m1-values-errors.xlsx`. Its chart package and workbook theme were rebuilt to Excel-clean form during the M8 release-gate work (2026-11-22). |
| `compat/cross-sheet-link.xlsx` | Ticket 32 structural-save fixture: `Sheet2` holds a formula, hyperlink and chart series pointing into `Sheet1`, and `Links` holds only a hyperlink into `Sheet1`. Inserting or deleting a row on `Sheet1` moves or breaks all of them in one transaction and one save; `Links` proves a sibling part is written even when no cell on it is dirty. |
| `compat/broken-internal-link.xlsx` | The broken-link convention (known deviation D-9, settled 2026-11-22): a hyperlink whose target is gone carries `location="#REF!"`. Opening, a no-op save and a later structural edit keep the marker and do not block the sheet. The Excel-oracle capture in `oracle/d9-broken-hyperlink/` records that Excel freezes the authored location instead; calcplus keeps the marker as the documented deliberate difference. |
| `compat/m2-grid.xlsx` | M2 grid-foundation workbook: one frozen row and one frozen column, a merged title range, an imported row height and column widths, and the font, fill, alignment and number-format styles the grid renders. The grid tests use it for the four-pane geometry, the merge anchor, the formatted cells and the scroll behaviour. |
| `manual/general-test.xlsx` | Manual smoke workbook. `Cover` has text, numbers, booleans, errors, dates, formulas with cached results, a merged header, a frozen top row and first column, fills and number formats. `Data` has 400 synthetic mixed-value rows under a frozen header for scrolling, selection, find and freeze-pane checks. |
| `oracle/m1-values-errors.xlsx` | Excel-openable value and error oracle fixture: text, inline string, number, boolean, constant errors, a formula with a cached result, a formula with an error result and text beginning with `=` both as a constant and as a formula result. The manual local Excel capture uses this workbook; its narrow error column makes display text unusable as error identity. |
| `expected/m1-values.json` | **Hand-authored** M1 fixture expectations produced by the fixture generator, compared with `1e-9` relative / `1e-12` absolute tolerance. They are not Excel 365 oracle goldens. |
| `expected/m3b-formulas.json` | **Hand-authored** M3B function, error/coercion/operator, date, reference, lookup and shim expectations, plus the data sheet those formulas read. `tests/engine-m3b.test.ts` compares them with `1e-9` relative / `1e-12` absolute tolerance. They are not Excel 365 oracle goldens. |
| `expected/m4a-number-formats.json` | **Hand-authored** M4A built-in number-format display corpus: one exact string for every ECMA-376 built-in id, including the pinned Gregorian en-US rendering of the locale-specific ids. Spaces in `expected` are significant. `tests/m4a-number-formats.test.ts` asserts the exact text. It is not an Excel 365 oracle golden. |
| `compat/csv-roundtrip.csv` | F24 CSV fixture: RFC 4180 quoting, embedded newlines and quotes, non-ASCII text, and displayed values that contain thousands separators. `tests/m6-csv.test.ts` round-trips it byte-for-byte. |
| `compat/producers/*.xlsx` | F22 producer matrix. `libreoffice.xlsx`, `openpyxl.xlsx`, `sheetjs.xlsx` and `xlsx-populate.xlsx` are generated by `scripts/fixtures/groups/producers.mjs`; `manifest.json` records the producer rows. `excel-365.xlsx`, `excel-2019.xlsx` and `google-sheets.xlsx` are **maintainer captures** and are absent until they are committed; the generator never fabricates them. |
| `oracle-manifest.json` | Stub manifest for stored Excel-oracle goldens. Status is `not-configured`: no Excel version, locale or committed golden exists yet. |

No real or personal workbook data is stored here. The Excel 365 oracle goldens
are not committed yet; the capture runs manually on the maintainer's PC. See
`scripts/oracle/README.md`.

## Producer matrix and repair-free check

`scripts/fixtures/groups/producers.mjs` writes the producer fixtures with
openpyxl, LibreOffice headless, SheetJS and xlsx-populate when those tools are
installed, normalises the ZIP container and document timestamps so regeneration
is byte-identical, and prints every producer it could not generate. The
`xlsx` package behind the SheetJS fixture is deliberately **not** a dependency
(0.18.5 advisory, maintainer review 2026-11-19): the committed fixture stands,
and `xlsx@0.18.5` is installed temporarily only when that fixture needs
regenerating. Excel 365,
Excel 2019 and Google Sheets exports are captured by the maintainer on their own
machine; drop the file into `compat/producers/` under the name in
`manifest.json`.

The local half of "opens without repair" is:

```bash
node scripts/verify-repair-free.mjs
```

It checks that relationships resolve, content types are complete, every XML part
is well formed and part names are safe, then loads each file with openpyxl and
converts it with LibreOffice when those are installed. The authoritative Excel
365 repair check is a manual release step.

## Number-format corpus gate

Run the committed built-in corpus locally with:

```bash
npm test -- tests/m4a-number-formats.test.ts
```

`ssf` is a differential oracle only (number-formats §1 and
testing-conformance §2). It is not a dependency, is not installed by this
repository and the corpus test never reaches the network. If `ssf` is already
available on the maintainer's machine, compare the same cases manually; a
mismatch is evidence to investigate, but the committed corpus remains the local
gate because there is no Excel 365 golden yet.
